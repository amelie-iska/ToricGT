## Implementation differences

| Component | Toric family | Mora-3 and transfer implications |
| --- | --- | --- |
| Main objective | Native `ToricTokenGT` reconstructs graph attributes on an input adjacency. Dense random-order LM learns conditional token probabilities under content-independent reveal order. OAI/ToricBLM uses causal next-token loss, with optional graph and reasoning streams. | The native trainer cycles through task-bound models and data readers. Use its typed source and target roles for nonbiological evaluations. Keep each Toric factorization explicit. BPB measures compression and needs separate graph/analogy metrics. |
| Backbone | Native graph tokens use toric features, endpoint embeddings and learned row IDs. Native attention uses a dot-product score with max-plus value aggregation. OAI uses GQA, RoPE, RMSNorm and ReLU². | Shared TokenGT uses explicit identifiers, softmax, pre-LayerNorm and GELU. Its optional tropical kernel uses a different score. Port tests for transported identity and consider the tiled winner-saving backward after measuring parity with Toric's score and tie rule. |
| Routing and identity | The native global Soft-MoE path mixed future tokens despite a reveal-rank attention mask. Regenerating row IDs changed aligned outputs under reindexing in the source audit. The dense random-order model has a distinct path. | Test prefix noninterference at the graph-to-logit boundary with rank order independent of row order. Test end-to-end equivariance with identifiers carried along by the permutation. |
| Tokenization | ConvexTok's byte fallback and priced edges give exact min-plus encoding over a byte-boundary DAG. The OAI path can consume token class, DAG, and local causal graph features as part of the primary model. | Mora's lossless payload codec and pooled neural payload encoding serve different purposes. Preserve the Toric token-level LM and pin tokenizer and feature checksums in each run. |
| Forest search | OAI FoT consumes selected hidden positions, with sparse activation, learned values, correction, consensus and trajectory-balance-style auxiliaries. Report topology is reconstructed over hidden positions. Native analogy diagnostics include entropic transport across hidden windows and directed relation residuals. | Mora provides bounded topology, quality, token decoding, trained analogy heads and an explicit hybrid teacher interface. The ordered topology uses `ADD_CHILD` and `CLOSE`. Reuse contracts for ancestor-only visibility, full trajectory records, independent verification and bounded results. The existence of these paths establishes implementation coverage. |
| GFlowNet semantics | The continuous implementation has successor-conditioned backward densities. The discrete and FoT path terms include shortcuts or normalizations that need separate interpretation. | Use explicit forward and backward terms for legal transitions, an explicit terminal event and immutable reward bindings. Record which traces are on-policy, beam-selected or edited. Test on an enumerable graph with known terminal probabilities. |
| Optimizer and transfer | General OAI trainer divides matrices into Muon and other groups into Adam/AdamW. The biomedical branch family adds μP base shapes and attention/readout/rate settings. | Mora's role ledger audits finite/widening axes, aliases and all enabled auxiliary owners under MuAdamW. Carry the ledger and paired-seed protocol over. Check transfer with the optimizer actually used. |
| Recovery | Both pinned OAI trainer lanes restore weights and step and recreate optimizers. Native trainers have some optimizer state. | Mora stages restore of optimizer, schedule, RNG and reader state. Use this state contract and add crash-safe publication. The inspected Mora save itself uses a new exclusive file and may leave a partial file after a write failure. |
| Structure capabilities | ToricBLM has structural auxiliary routes. The supplied audit reports an identifiability problem in its velocity branch and separate contact/distogram supervision. | Mora has source-specific structure and assay interfaces. The upstream RFD4-Proteina model card documents a biomolecular generator. The `amelie-iska` fork remains unverified in the public refs and checked local location, so the upstream card establishes only upstream capabilities. The implementation plan covers symbolic reasoning and nonbiological data. |

### Nonbiological data layout

Build a fresh versioned corpus under the branch worktree with immutable source references. Keep large payloads and intermediate outputs outside Git. The source manifest records source/version, license, row/group counts, split decisions and artifact hashes. The typed reasoning record carries a problem ID, a family and role, typed nodes and edges, visible prefix, permitted transitions, target output and provenance. Token and graph projections derive from the same row ID. Candidate metrics and evidence from model rollouts belong with the run, distinct from source observations.

Build grouping over small identity records before writing feature-heavy shards. Count unique examples, groups and consumed tokens separately. Keep a seen-training and retrieval-exposure ledger. Reconcile upstream benchmark IDs and user-provided split policy before splitting. Test the two known legacy normalization regressions in CI. Cross-source admission remains a separate dataset-level check. This branch changes the two normalization rules and leaves existing source artifacts in place.

### Analogical reasoning and FoT

Use the [Bi et al. FoT reference](https://proceedings.mlr.press/v267/bi25a.html) for sparse activation, heterogeneous branches, correction and dynamic consensus. Current Toric displays can show activation and candidate topology on a given sequence. A teacher-forced trace takes target IDs and per-token NLL, and its lines represent reconstructed edges. Evaluate generated answers with independent verifiers and record real rollout actions before interpreting diagrams as search traces.

- Yasunaga et al. supports generating candidate exemplars before answering. Compare with fixed exemplars, random exemplars and train-only retrieved exemplars, with equal prompt tokens and multiple independently proposed candidates. [Analogical prompting](https://arxiv.org/abs/2310.01714)
- Minegishi et al. operationalizes analogy as transfer of compositional relations between categories and separately measures embedding alignment and Transformer application. Measure edge-type and direction preservation under entity substitution, composed path agreement, and robustness to incomplete/noisy mapping. Treat representation alignment and answer accuracy as different measurements. [Emergent analogical reasoning](https://arxiv.org/abs/2602.01992)
- Shen et al. separates cross-domain relation identification from solution generation. Compare diversity of verified edits at a fixed budget, and count unique successful outcomes separately from lexical or embedding dispersion. [Cross-domain analogical reasoning](https://arxiv.org/abs/2605.11258)
- Korchinski et al. gives a co-occurrence mechanism for linear offsets in word representations. Include additive offsets as a transparent baseline and challenge it using identical node/relation counts and different attachments. [Linear analogies](https://arxiv.org/abs/2505.18651)

Start with an exact verifier on small anonymous typed forests. Use learned node embeddings to shortlist mappings, verify them with directed edge and composition checks, then select globally consistent root correspondences. For ordered trees keep child order where meaningful. For forests allow tree permutation where roots are exchangeable. For partial analogies report coverage and ambiguities; do not force assignment of all roots. Add answer scoring only after the oracle can reject hard negatives. Plot alignments in two dimensions for inspection and compute scores in the original representation. Use a fresh split by motif and transformation composition, including depth and branch-count extrapolation and unseen root permutations. Report per-scope top-1, tie rate, invalid-candidate false accepts, witness accuracy, verified answer accuracy, unique verified solutions, tokens expanded and elapsed time.

### Eligible general-model 24 + 2 campaign design

Initial shape check used pinned trainer `e8ec408` and μP `1981497`, nine layers, eight query heads, four KV heads, tied ConvexTok-2048 vocabulary. The core is 10,027,707 parameters at width 368 and 79,020,411 at width 1072. The 368/448/1072 family passed a one-update CUDA smoke on the RTX 4090 with MuAdamW, BF16 autocast and a fixed 128-token synthetic arithmetic batch. Hidden update RMS was 0.125, 0.121 and 0.123, respectively. Peak allocated memory was 199, 282 and 1,507 MiB. These figures establish short-batch feasibility. Production-length throughput and final optimizer transfer need independent checks. Preserve depth, GQA ratio, tokenizer and finite dimensions across the family. Count all enabled heads and optimize membership before freezing exact target width.

1. Use fixed training/validation groups, a frozen token budget and the same accumulation, context and optimizer convention across widths. Run a short single-device restart smoke with deterministic data, finite gradients and validation parity. Measure loaded token throughput and peak allocation with representative batches before setting an epoch size.
2. Fix one tested scaling policy and one main optimizer for the counted stage. Keep any Muon versus MuAdamW comparison in a separate short coordinate-check experiment. Compare normalized activation RMS, feature update RMS, attention logit scale and update/weight ratios over ordered widths. Freeze the family only after the results support it. [μTransfer paper](https://arxiv.org/abs/2203.03466)

Checkpoint each epoch with a validation ranking and write a manifest for the three best eligible checkpoints. Preserve other files under the working agreement. Limit any future authorized release to those ranked files and qualified dataset/model cards.

### Current evidence and handoff

The synthetic oracle benchmark is an executable scope test. At seed 17 with 16 cases per scope it accepts 48/48 gold targets and 0/240 structure-matched negatives. The bag/count offset ties all six candidates and scores 1/6 with tie adjustment. The stronger anchor-payload-size offset scores 26.39% on the same cases. These are properties of the generated cases and exact verifier. The page example independently illustrates a hand-authored role/payload swap and an incorrect swap at all three scopes.

The ordered arithmetic benchmark uses 16 query groups per scope with three exemplar edits per fixed query and candidate set. At seed 17, the exact verifier accepted one correct result for each of 144 cases and accepted zero of 432 negative candidates. Tie-adjusted top-1 for typed counts was 94.10% with the exemplar offset and 18.92% without it. Seed 29 reproduced exact certification at 144/144 and 0/432 false accepts, with retrieval at 95.83% and 20.31%. These are deterministic fixture and feature results. The offsets exploit measurable changes in hand-engineered counts. Run `python3 src/toricgt/toricmora_analogy.py --task right-identity --seed 17` from the branch checkout.

The payload-exchange verifier scopes anchor discovery to the selected subtree while certifying the full output, including untouched sibling context. A regression fixture adds a duplicate set of matching anchors in an untouched sibling. The arithmetic verifier preserves directed operand roles and applies one pass over sites that qualify in the original input. Its tests distinguish that pass from repeated rewriting and reject changes outside the selected subtree or edits limited to one forest component.

The prior simplex report compares a representation to a noisy copy of itself. The archived simplex summary also credits collapsed triangles without always checking that a two-vertex image is an edge in the target. Treat historical validity scores as reconstruction diagnostics. The next simplex validation should check the deduplicated image of each simplex against the target complex, then compare against independently constructed structures with directed edge and role constraints.

Checkpoint-backed CPU smoke restored the June general-text r011 step-25,000 backbone and FoT head with archived settings and exported diagnostic traces for arithmetic, a tree and a forest. Trace endpoint and order checks pass. A last-token perturbation changed earlier LM logits by 0 in each of three CPU cases. Direct 24-token greedy continuations scored 0/3 by the strict leading-integer answer rule on separate addition, tree-counting and forest-counting prompts. The original checkpoint has an empty hyperparameter map. This makes archived launch settings material to reproduction. Use `scripts/export_oai_fot_trace.py --parameter-golf <pinned-path> --checkpoint <checkpoint> --tokenizer <tokenizer> --hyperparameters-json <recorded-settings> --prompt <prompt> --output-json <path>`. Use `PYTHONPATH=src python -m toricgt.toricmora_analogy --seed 17 --examples-per-scope 16` to reproduce the oracle benchmark.

Native causal Soft-MoE now uses the graph's reveal rank for expert dispatch, including same-rank nodes and edges. The test checks exact early-logit invariance, zero gradient from earlier logits into later inputs, and a missing-rank error. Dispatch reuses the original expert weights. The reference implementation chunks distinct ranks and recomputes dispatch on backward. Its work grows with both token count and distinct rank count. Large-graph throughput remains unmeasured.

This iteration extends the standalone symbolic benchmark with ordered arithmetic trees, exact scoped right-identity verification and the unshifted retrieval baseline. The next symbolic search milestone is the matched-budget held-out comparison above. Dataset-level transitive grouping and crash-safe trainer recovery remain separate milestones. The 24 + 2 matrix is a prospective general-model experiment. No campaign run has been started.
